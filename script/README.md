# かおディスバトル（仮）

自分で描いた顔でCPUとツッコミ対決する、日本語ブラウザゲームです。依存ライブラリ・ビルド・APIキーなしでデモを遊べます。Gemini・GPT APIまたはOllamaを使うと、AIが採点とCPUの返答を担当します。CPU戦の合計ダメージランキングに対応しています。オンライン対戦は含みません。

## 固定URLでクラウド公開

PC停止中も使える公開方法は [Render無料Webサービス＋Turso無料DBの手順](DEPLOY.md) を参照してください。ngrokの確認操作が不要な固定URLを使えます。無料枠の休止・起動待ちはあります。ローカル起動や既存のngrok共有も引き続き利用できます。

## 起動

Python 3.10以降を用意し、このフォルダで実行します。

```bash
python3 server.py
```

ブラウザで **http://127.0.0.1:8000** を開いてください。終了は Ctrl+C。ポートを変える場合は `python3 server.py --port 8001`。HTMLを直接開かず、HTTPサーバー経由で利用してください。

1. **タイトル**：「あそぶ」で開始します。
2. **簡単なルール**：「描く→ひとこと→3回ずつ」の説明を読みます。
3. **難易度**：「やさしい・ふつう・ガチ」から選びます。初期設定は「やさしい」です。
4. **顔を描く**：ペン・消しゴム・色・太さで描き、横の完成形を確認します。元に戻す（直近50操作）・全消去に対応。敵を選んで対戦へ進みます。白紙では開始できません。
5. **対戦**：顔・HPバー・攻撃入力だけの画面です。あなた→CPUの順で3回ずつ攻撃します。
6. **結果**：勝敗と残りHPを表示し、再戦・別の相手・描き直し・タイトルへ進めます。

同じURL内で1画面ずつ切り替えます。AI選択や接続設定のUIはプレイヤー画面にありません。**使用AIは運営側が `config.py` の `JUDGE_MODE` とモデル名で設定**し（同名の環境変数を優先）、キーは `.env` 等で設定します。接続できない場合は開始を止め、自動で別のAIやデモには切り替えません。APIなしで試す場合は `JUDGE_MODE = "demo"` にして再起動してください。デモであることはルール画面に明示します。

ブラウザの戻る・進むにも対応し、採点・演出中の移動を抑止します。スマホでは入力欄をタップしたときだけキーボードを開き、送信すると閉じます。実際のキーボード表示は端末・ブラウザにも依存します。

初期HPは100、1攻撃は0〜30ダメージです。全6攻撃の後の残りHPで勝敗を決め、同じなら引き分けです。デモ判定ならAPI接続なしで試せます。

## お絵描きツール

ペン・消しゴムに加え、バケツ・直線・丸／楕円・スポイトを使えます。マウスとスマホのタッチ操作に対応します。

- **バケツ**：色を選んで、塗りたい部分をタップ。つながった同色の領域を塗ります。閉じた輪郭の中を塗ると外へ漏れません。線が開いている場合は外側もつながった領域として塗られます。
- **直線・丸／楕円**：始点から終点へドラッグして描きます。色と太さを使い分けられます。
- **スポイト**：絵をタップして色を取り、ペンへ戻ります。透明部分は白として取り込みます。
- バケツや図形も「元に戻す」と「全消去」の対象です。色を変えてもバケツは選択したままです。白だけで塗ったキャンバスは白紙と判定します。

塗りつぶした顔の完成形プレビューでも、十分な大きさの色の領域を輪郭として扱います。バケツは塗った範囲を保存し、プレビュー更新のたびに領域探索をやり直しません。`tests/drawing_tools_browser_check.py` とブラウザの `/tests/index.html` で塗り境界・undo・図形・スポイト・タッチ・プレビューを検証します。

## 効果音

カットインに短いスイープ音、被弾に軽い打撃音、ダメージ0に控えめな音、勝ち・負け・引き分けに短いメロディを付けています。控えめなBGMにも対応しています。Web Audioで合成するため音声ファイルのダウンロードや追加ライブラリは不要です。

タイトルの「♪ 効果音を試す」で音をオンにして試聴できます。右上のスピーカーボタンでオン・オフを切り替えます。初期設定はオンで、消音の選択は同じブラウザに保存します。スマホの自動再生制限に対応し、最初のクリック・タッチ・キー操作後に音を準備し、音声の再開が完了してから再生します。中断後の再開にも対応します。バックグラウンドでは消音し、音声非対応や再生できない場合もゲームは続けられます。端末の音量・マナーモードにも依存します。

`tests/sound_browser_check.py` で合成音の波形・音量範囲・終了、消音と設定の復元、非対応時の動作をブラウザ検証します。ヘッドレス環境では実際のスピーカーの聞こえ方は未確認です。

## Geminiで顔の特徴を使い回す

通常のCPU戦では、最初の攻撃時に自分とCPUの2枚の顔をGeminiへ送り、採点と同時に輪郭・目・眉・鼻・口・髪・アクセサリー・配置の特徴を抽出します。サーバーが対戦ごとの特徴メモを保持し、2・3回目は画像を添付せず、メモと発言・履歴を送って採点とCPUの返答を作ります。追加の解析リクエストは増やさず、3ラウンドでAI呼び出しは3回のままです。

各攻撃に「攻撃対象の特徴」を分けて渡します。人間の発言はCPUの顔に照合し、CPUの返答は人間が描いた顔だけを狙います。初回の画像ラベルと特徴メモの項目、短縮出力スキーマにも所有者と攻撃対象を明記しています。特徴メモの読み取り漏れや誤認識は後続の採点にも影響します。採点理由には「初回の顔特徴を使用」と明示し、新しく画像を見たとは扱いません。再戦・別の敵・描き直しでは新たな対戦メモを作り、対戦終了・セッション失効・サーバー再起動で破棄します。メモはDBへ保存しません。

この最適化はランキング対応のGemini対戦セッションで使います。GPT・ローカルLLM・デモの方式は従来通りです。ランキングセッションに初期接続できず通常のGeminiゲートウェイに戻った場合は、画像を各ラウンドで送る旧方式になります。実AIでの速度改善幅は未計測です。

## Geminiの生成量と所要時間

Geminiへ依頼する採点JSONは内部の通信だけ短いキーと数値配列にし、受信後に従来の項目名へ戻します。顔一致・刺さり・工夫・新鮮さの4項目と根拠・理由を残し、CPUの一言も生成します。初回の特徴メモと2・3回目の画像省略も維持します。配列の項目数は[Geminiの構造化出力](https://ai.google.dev/gemini-api/docs/structured-output)に従って指定し、受信後に各項目の上限を検証します。JSONのサンプルでは260→140バイトですが、実際のトークン数や短縮秒数は内容で変わります。

サーバー端末に `Gemini API 3.94s; images=2; output_tokens=318` のようにAPI往復時間・画像数・出力トークン数を表示します。発言・顔・キー・HTTPヘッダーはこの計測ログに出しません。エラー時はHTTP状態と経過時間を記録します。初回は画像2枚、通常の2・3回目は0枚になることを確認できます。計測には外部APIの通信と応答待ちも含まれます。

## 控えめなBGM

ゆっくりしたテンポ（96 BPM）の、柔らかい音の20秒ループをWeb Audioで合成します。軽いメロディと低音のみで、強いドラムや追加の音声ダウンロードはありません。音量は効果音より控えめです。

右上の「♫」でBGMだけをオン・オフできます。効果音の「🔊」とは独立し、設定をブラウザに保存します。初期設定はオンですが、最初のタッチやクリック後に始まります。別タブやバックグラウンドに移ると停止し、戻ると再開します。端末やブラウザによっては再度画面のタップが必要です。

`tests/music_browser_check.py` で音量範囲・継ぎ目・無操作時の再生なし・独立した消音・重複再生防止・再開・設定保存を確認します。実スピーカーでの聞こえ方は未確認です。

## 結果画面で採点を振り返る

結果画面の「今回の採点を見る」を開くと、3ラウンド分の双方の攻撃文・ダメージ・採点理由を確認できます。CPUの難易度補正やデモ判定の説明も含め、実際にその対戦で表示したログを使います。ランキング登録やAIへの再問い合わせは不要です。初期状態は閉じておき、再戦すると前の表示を消します。公開登録しなければ、この振り返りを表示するだけでログが公開されることはありません。

## CPU戦の合計ダメージランキング

CPUへの3回の攻撃で与えた合計ダメージ（最大90）を競います。結果画面で合計を確認し、名前を入力して「顔・記録・ログを公開する」を押すと、描いた顔・記録・双方の攻撃文・採点理由が公開されます。実名や個人情報を名前に使わないでください。タイトルと結果画面の金色の「🏆 ランキングを見る」ボタンから開けます。

- やさしい・ふつう・ガチごとに上位20件を表示。同点は同順位です。記録は1対戦につき1件で、同じ名前の別対戦も載ります。
- 一覧に描いた顔のサムネイルを表示します。顔は必要になった行から読み込みます。ランキングの各記録を押すと、その対戦の3ラウンドのログを専用画面で表示します。同名の記録があっても対戦ごとに区別します。追加前の記録には画像なしのプレースホルダーや「ログなし」と表示し、既存の点数は維持します。ログを見るためにAIへ再問い合わせはしません。
- 採点方式（Gemini / GPT / ローカル / デモ）ごとに分離し、管理側で現在選んでいる方式の記録を表示します。デモ判定では画像を解析しません。
- サーバーが3ラウンドの採点結果を保持し、合計します。ブラウザから送った合計値やHPを登録点数には使いません。途中終了は登録不可、再送信による二重採点と二重登録を防ぎます。
- ランキング対象の対戦採点は同時に2件まで。混雑時は再送信でき、HPは変わりません。採点失敗時も両者のスコア・履歴を確定しません。
- ランキングの保存先は `.data/rankings.sqlite3`（Python標準のSQLite）です。サーバーを再起動しても登録済み記録は残ります。DBファイル自体はGit管理・Web配信の対象外です。登録済みの顔は専用のPNG配信API、ログは専用の閲覧APIで公開します。
- 永続保存するのは名前・採点方式・難易度・敵ID・合計ダメージ・登録日時と、登録した対戦の3ラウンド分の双方の攻撃文・ダメージ・採点理由・残りHPです。登録した対戦の自分の顔画像も保存・公開します。未登録の顔画像はDBへ保存しません。名前は同じブラウザの次回入力用にローカル保存します。
- 未登録の対戦はサーバーのメモリのみで、30分操作がなければ失効します。サーバー再起動や画面更新でも未登録の結果は引き継ぎません。登録は結果画面を離れる前に行ってください。
- ランキングへの初期接続に失敗した場合、通常のCPU戦は続けられますが、その対戦はランキング対象外と結果に表示します。

追加の起動操作は不要です。既存のサーバーを停止し、いつもの `python3 server.py` または `uv run share.py` で起動し直して画面を更新してください。`.data` はサーバー実行ユーザーが書き込める場所に置きます。ランキングは同じサーバーの利用者で共有されます。アカウント認証・名前の一意性・ランキング管理画面・対人戦は未実装です。

検証：`python3 -m unittest discover -s tests -q`。ブラウザ検証 `tests/ranking_browser_check.py` は、デモ専用のテストサーバー（8001）と一時DB、CDPブラウザ（9222）で実行します。CPU戦3ラウンドから登録・表示・再読み込みまでを外部AIなしで確認します。ブラウザ検証スクリプト同士は順番に実行してください。

## 描いた輪郭に合わせた3Dの顔

濃い線で輪郭を大きめにぐるっと閉じて描くと、その形から丸みと厚みのある3Dメッシュを作ります。WebGLで前面と背面を描画し、目・鼻・口・髪などの絵を前面に貼ります。横長・縦長・四角い輪郭にも対応し、CPUもそれぞれの輪郭で立体化します。メガネやひげも手描きの線として表面に載せます。追加ライブラリや3D生成APIは不要です。

- キャンバス横の完成形は描画中も更新します。消しゴム・元に戻す・全消去も反映します。
- 待機中は浮きながら少し回転し、マウスに合わせて傾きます。攻撃・被弾・カットインにも同じ3Dの顔を使います。
- 輪郭が閉じていない、薄すぎる、小さすぎる場合は丸い形を使い、プレビューで案内します。最大の閉じた領域を顔とみなす簡易判定のため、線が複雑に交差する絵や大きなくぼみは近似形になります。顔の輪郭につながった髪や飾りは形に含めますが、離れた装飾は切れる場合があります。
- 鼻や髪の各パーツの厚みを画像から個別に推測する機能は含みません。顔全体を輪郭に沿った立体にする方式です。
- WebGLが使えない端末では、輪郭を保った陰影つきの2D表示を使います。丸い粘土に戻さず、縦長・横長などの外形を維持します（立体回転はなし）。コンテキスト喪失中は画像表示に戻し、復帰すると3D表示を再開します。モーション軽減設定にも対応します。
- 攻撃時は顔と発言のカットイン→被弾・大きなダメージ数値の順に再生します。カットインは文章の長さに応じて2.5〜5秒、被弾は1.1秒表示。自分のカットイン中に採点を進め、両方が終わってからHPを更新します。CPUのカットインも最後まで表示し、演出中の二重送信を防ぎます。採点が演出より長い場合は「採点中…」と経過秒数を短く表示します。
- 対戦中は顔・HPバー・攻撃入力を表示し、見出し・名前・HP数値・説明・採点理由・ログは隠します。決着時は結果と再戦操作、失敗時はエラーを表示します。

元の絵は変更しません。AI採点には影や立体効果を付ける前のPNGを送り、モデル生成はブラウザ内で行います。

## CPUの種類

お絵描き画面の「対戦するCPU」で、6種類から選べます。初期設定の「おまかせ」は前回と違う敵を選びます。

- まめお：少しゆがんだ丸顔、点の目、曲がった鼻。
- のびお：縦長の顔、短い横目、長い鼻。
- かくべえ：ゆがんだ四角い顔、四角い目、一直線の口。
- ぽてすけ：横に広い顔、離れた目、小さな丸い口。
- さんきち：三角の顔、つり目、への字の口。
- ひげもち：もち形の顔、手描きの丸メガネ、くるんとしたひげ。

敵はすべてプレイヤーの落書きに近い、塗りのない手描き線で描いています。輪郭はペンで描いたような不均一な曲線にして、プレイヤーの初期ペンと同じ色・太さを使っています。粘土本体も輪郭から生成するため、細長い顔・横広の顔・三角の顔などに合わせて3Dの形そのものが変わります。輪郭からの3D化・表面の絵・攻撃演出はプレイヤーと共通です。旧キャラクターは置き換えています。

「同じ顔で再戦」は同じ敵と再戦し、「別の敵と対戦する」は自分の絵を保って新しい敵に切り替えます。全員HP100・3ラウンドでルールは共通です。CPUの強さは「やさしい」（初期設定、CPUダメージ60%）、「ふつう」（80%）、「ガチ」（補正なし）から選べます。端数は四捨五入し、CPUの最大ダメージは順に18・24・30です。プレイヤーの採点は変えず、CPU側の補正はログに表示します。再戦は同じ難易度を維持します。画像対応AIには選ばれた敵の顔をPNGにして渡します。デモ判定のCPU発言は従来どおり定型です。顔の定義は `enemies.js` にまとめています。

## スマホ・他のPCからアクセスする

同じWi-Fi / LAN内で使う場合、サーバーを起動中ならCtrl+Cで止め、PCで次を実行します。

```bash
python3 server.py --lan
```

Linuxでは、別のターミナルでPCのLAN内IPアドレスを確認できます。

```bash
hostname -I
```

たとえばPCのIPが `192.168.0.200` なら、同じWi-Fiのスマホで **http://192.168.0.200:8000** を開きます。スマホで `127.0.0.1` や `localhost` を指定するとスマホ自身を指すため接続できません。PCのIPはネットワークにより変わります。

- `--lan` を省略すると、従来どおりPC自身だけから接続できます。別ポートなら `python3 server.py --lan --port 8001`。
- APIキーはPC側にだけ設定します。スマホでキーを入力する必要はありません。各端末で別々にCPU戦を遊べます。対人戦にはなりません。
- 接続できない場合は、PCとスマホが同じWi-Fiか、ゲストWi-Fiで端末間通信が遮断されていないか、PCのファイアウォールが指定ポートを遮断していないか確認してください。
- ログイン認証はありません。同じLANから開ける人はPC側のAPIキー経由でAIを利用できるため、信頼できるLANで使用してください。これはインターネット公開用の構成ではありません。

## 別のWi-Fi・モバイル回線から共有

### 毎回変わらないURLで共有（ngrok無料プラン）

[ngrokの無料プラン](https://ngrok.com/docs/pricing-limits/free-plan-limits)には、アカウントごとに固定の開発用ドメインが1つ割り当てられます。名前は自由に選べませんが、再起動後も同じ割り当てURLを使用できます。最初の1回だけ設定します。

1. [ngrok](https://dashboard.ngrok.com/signup)で無料アカウントを作成します。
2. このフォルダで `uv run setup_share.py` を実行します（Pythonだけなら `python3 setup_share.py`）。
3. [Your Authtoken](https://dashboard.ngrok.com/get-started/your-authtoken)からトークンをコピーし、非表示入力欄に貼り付けます。GeminiのAPIキーとは別です。
4. [Domains](https://dashboard.ngrok.com/domains)に表示された、末尾が `.ngrok-free.app` または `.ngrok-free.dev` の割り当てURLを貼り付けます。
5. 起動中のサーバーをCtrl+Cで止め、`uv run share.py` を実行します。以後もこのコマンドで同じURLを使用します。接続完了までは起動ログを確認してください。

設定は既存のGeminiキーを残して `.env` に保存します。`SHARE_PROVIDER=ngrok`、`NGROK_AUTHTOKEN`、`NGROK_URL` が設定され、毎回の入力は不要です。トークンはコマンド引数やブラウザに渡さず、ngrok子プロセスの環境変数だけに渡します。HTTPリクエストのローカル検査も無効にします。

このPCには `.tools/ngrok` を配置済みです。別環境では[公式ダウンロード](https://ngrok.com/download/linux)からngrokをインストールしてください。Linux x86_64なら次の方法も使えます。

```bash
mkdir -p .tools
curl -fL https://bin.ngrok.com/c/bNyj1mQVY4c/ngrok-v3-stable-linux-amd64.tgz -o /tmp/kao-ngrok.tgz
tar -xzf /tmp/kao-ngrok.tgz -C .tools ngrok
chmod +x .tools/ngrok
```

無料版には通信量・リクエスト数の上限と、ブラウザで最初に開くときの確認画面があります。「Visit」を押してゲームを開いてください。通常は同じドメインについて7日間確認が省略されます。[無料枠の公式説明](https://ngrok.com/docs/pricing-limits/free-plan-limits)

URLが固定でも、PCと `share.py` が停止している間は遊べません。常時稼働のサーバーは含みません。設定後も `uv run share.py --provider cloudflare` で従来の一時URLを使えます。環境変数 `SHARE_PROVIDER` がある場合は `.env` より優先し、`--provider` 指定が最優先です。ngrok接続に失敗した場合、ランダムなURLへ自動で切り替えません。

### アカウント不要の一時URL（従来のCloudflare）

Cloudflare Quick Tunnelで一時的なHTTPS公開URLを作ります。ルーターのポート開放やCloudflareアカウントは不要です。[公式説明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

このPCでは `.tools/cloudflared` を配置済みです。別のLinux x86_64環境で使う場合は、次で取得します（他のOSは公式のcloudflaredをインストールしてください）。

```bash

curl -fL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o .tools/cloudflared
chmod +x .tools/cloudflared
```

起動中の `server.py` をCtrl+Cで止めて、次を実行します。

```bash
python3 share.py
```

1. Geminiキーが未設定なら入力します。設定済みの環境変数もそのまま使えます。
2. ターミナルに出る `https://〜.trycloudflare.com` をスマホで開きます。モバイル回線でも接続できます。
3. パスワードやログインなしで、そのまま遊べます。

PCとこのコマンドを起動している間だけ使えます。終了はCtrl+C。Cloudflareの一時URLは再起動すると変わります。ポートが使用中なら `python3 share.py --port 8001`。このCloudflare方式には固定URL・常時稼働のホスティングは含みません。各端末でCPU戦を遊ぶための共有です。

共有URLにログイン認証はありません。APIキーはPythonサーバーだけが使い、ブラウザやトンネルの子プロセスには渡しません。URLを知る人はあなたのAI利用枠を使えるため、遊ぶ相手にだけ教えてください。トンネルサービスを経由して画像や発言が通信されます。Quick Tunnelは一時的なテスト用途で、接続の継続保証はありません。

`config.py` でモデルを変更できます。変更後はサーバーを再起動し、ブラウザを再読み込みしてください。

```python

```

- キーは `setup_key.py` で保存、起動時の非表示入力、または環境変数 `GEMINI_API_KEY` で設定します。JavaScript・`config.py`・チャットにキーを書かないでください。`GEMINI_MODEL` 環境変数はファイルより優先します。`.env` は自動で読み込みます。

画面に「モデルがAPIで見つかりません」と出る場合は、使用モデル名を確認してください。旧設定の `gemini-2.5-flash-lite` からは `gemini-3.1-flash-lite` に変更します。環境変数 `GEMINI_MODEL` があると `config.py` より優先されるため、設定をファイルに揃えるにはサーバーを止めて同じターミナルで実行します。

```bash

```

API仕様：[画像入力](https://ai.google.dev/gemini-api/docs/generate-content/image-understanding)、[構造化出力](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)。

## 判定の待ち時間

Gemini/GPTモードは1ラウンド1通信です。待ち時間を抑えるため、共通指示の重複を削り、CPU返答は60文字、採点理由は30文字、画像根拠は20文字以内をモデルに指示しています。Geminiの出力上限は1,000トークン。送信画像は384pxに縮小し、描画キャンバスと表示用画像は640pxのままです。細い線などの採点精度は実際の絵で確認してください。

APIの応答後に入れていた0.9秒の待機を削除し、攻撃演出は各0.65秒（計1.3秒）に短縮しました。判定待ち中は攻撃ボタンを待機表示にします。この表示は通信を含む判定全体の時間で、演出時間は含みません。無料枠の混雑や通信環境による待ち時間は残ります。実APIの改善幅は、この環境ではキー未設定のため未計測です。

GPTを使う場合は `config.py` で明示的に切り替えてください（別途API従量課金）。

```python
JUDGE_MODE = "gpt"  # "local": Ollama / "demo": 接続不要
OPENAI_MODEL = "gpt-5.4-mini"
```

[OpenAI APIの管理画面](https://platform.openai.com/api-keys)でAPIキーを取得し、サーバーを起動するターミナルで環境変数に設定してください。**APIの従量課金が発生し、顔画像と発言をOpenAIへ送ります。** キーをチャットやブラウザ、`config.py` に貼り付ける必要はありません。

Bashで、キーを履歴に残さず非表示で入力して起動する例です。

```bash
read -rsp 'OpenAI API key: ' OPENAI_API_KEY
export OPENAI_API_KEY
printf '\n'
python3 server.py
```


- GPTモードは**プレイヤー採点・CPU返答生成・CPU採点を1回のAPI呼び出し**で返します。1試合は通常3回。失敗時に自動再送はせず、画面から再送信できます。失敗したリクエストにも処理状況によって料金が発生する可能性があります。
- モデルは `OPENAI_MODEL` 環境変数でも変更できます。画像入力と構造化出力に対応するモデルを指定してください。GPT-5.4系は待ち時間を抑えるため `reasoning.effort=none` を指定しています。
- 顔はPNGで送信し、画像の `detail` は `low`。細かい線の認識が不足する場合は `server.py` の `run_gpt_round` で調整できます。
- API呼び出しは60秒でタイムアウトします。エラー時はラウンドのHP・履歴を変更しません。
- `OPENAI_API_KEY` はサーバーの環境変数または `.env` で設定します。設定API・モデル状態API・静的ファイル配信にキーを含めません。`.env` は自動で読み込みます。
- 実際の待ち時間は回線、モデル、APIの混雑で変わります。この環境にはAPIキーがないため、実GPTの速度・採点品質は未確認です。モックでゲーム・API連携・エラー処理を検証しています。

仕様は [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[構造化出力](https://developers.openai.com/api/docs/guides/structured-outputs)、[画像入力](https://developers.openai.com/api/docs/guides/images-vision) を参照してください。

## ローカルLLM（Ollama）

[Ollama](https://ollama.com/)をインストールし、使いたいモデルをあらかじめインストールしてください。本アプリはモデルの自動ダウンロードを行いません。

```bash
ollama serve
ollama list
```

Ollamaの常駐サービスが既に動いていれば `ollama serve` の追加起動は不要です。

使用モデルは **`config.py`** で変更できます。

```python
JUDGE_MODE = "local"  # Ollamaを使う場合。"demo" ならデモ判定
OLLAMA_MODEL = "qwen3-vl:4b-instruct"
OLLAMA_URL = "http://127.0.0.1:11434"
```

モデルは先に `ollama pull qwen3-vl:4b-instruct` などで取得してください。モデルが新しいOllamaを要求する場合は、先にOllama本体を更新します。

**設定変更後に `server.py` を再起動し、ブラウザを再読み込みすると、指定モデルに自動接続します。** モデル名をHTMLやJavaScriptに書く必要はありません。未取得・接続失敗時には理由を表示してバトル開始を止めます。デモへ切り替える場合は `config.py` の `JUDGE_MODE` を `"demo"` にして再起動してください。


- 標準接続先は `http://127.0.0.1:11434`。変更はサーバー起動時の環境変数 `OLLAMA_URL` で指定できます。接続先は自分で管理するサービスを指定してください。
- `/api/show` の `capabilities` に `vision` があるモデルには、対象の顔をPNG画像で渡します。描いた顔はCPUの発言生成とCPU攻撃の採点にも使用します。
- **テキスト専用モデルでは顔画像を渡しません。** ルール画面でサーバーのAIが採点すると案内し、言葉の刺さり・工夫・重複を採点。CPUにも画像を見たかのように断言しないよう指示します。画像への一致点は0点扱いで、ダメージ上限は18です。
- LLMは、顔一致0〜10・刺さる毒舌の鋭さ0〜10・たとえの工夫0〜5・新鮮さ0〜5を項目別に返し、サーバーが合計して0〜30ダメージを決めます。顔一致4以上・刺さり3以上のときに19以上のダメージが可能です。顔一致4以上・刺さり3〜5のシンプルなツッコミには+6ダメージを加え、最大30に収めます。重複（新鮮さ0〜1）は上限8、同文（句読点・空白等の違いを除く）は上限2。テキスト専用モデルでは顔一致を必ず0にするため上限18です。ログに内訳と画像の根拠を表示します。ただし、モデルの採点の公平性・指示遵守は保証できません。
- Ollamaモードは1ラウンドにつき、プレイヤー採点→CPU発言生成→CPU採点の3回推論します。モデルとPCによって待ち時間が変わります。各サーバー呼び出しは120秒でタイムアウトします。
- 通信・応答形式のエラー時にはそのラウンドのHP・履歴を更新せず、入力を残して再送信できます。デモへ勝手に切り替えません。
- OllamaモードではAPIキーは不要です。GPTモードでは上記の環境変数を設定してください。

Ollama APIの仕様: [Chat](https://docs.ollama.com/api/chat)、[モデル情報](https://docs.ollama.com/api/show)。Ollamaモードの顔画像と発言はPythonサーバー経由で設定したOllamaへ送ります。CPUランキング対象の対戦中は、顔画像と発言履歴をサーバーのメモリに一時保持します（最後の操作から30分で失効し、採点中は保持）。公開登録した対戦の自分の顔画像をデータベースへ保存します。未登録の画像はDBへ保存しません。ランキングに登録した対戦の発言・採点理由は公開ログとして保存します。未登録の発言履歴はメモリのみです。GPTモードでは送信先がOpenAI、GeminiモードではGoogleになります。画面を更新するとお絵描き・対戦内容は消えます。

## 毒舌スタイル

CPUは、描いたキャラクターの顔の形・パーツ・配置を大げさにイジる、強めの毒舌で返します。`config.py` の `ROAST_STYLE` で口調を変更できます。変更後はサーバーを再起動してください。

短い言葉でも遊びやすい採点にしています。画像に合うシンプルなツッコミ（顔一致4以上・刺さり3〜5）は+6ダメージ。「眉毛ふとっ」を8/4/0/5と評価した場合は23ダメージです。長い文章や凝ったオチは必須ではなく、同文・似た発言の減点と最大30の制限は維持します。デモでも「眉毛、海苔」のような短いたとえを評価します（デモは画像未解析）。

きつい言葉や悪口という理由だけで0点にする処理は廃止しました。ダメージは顔の特徴との一致と、その特徴をえぐる毒舌の刺さりを重視します。単なる部位の指摘や、無関係な罵倒語の付け足しだけでは高得点にしません。実際の人間が傷つく度合いを測定しているわけではなく、描いたキャラクターへのディスの鋭さを評価します。デモCPUの定型文も毒舌寄りです。実LLMの実際の口調はモデルにも左右されます。

## デモ判定

画像を解析しない仮採点です。たとえの言い回し・顔の部位を表す単語・遊びのある単語を検出し、過去の発言との文字列・二文字組の類似度で重複を減点します。文字数や過激さによる加点はありません。CPUは3種類の定型文です。実際の顔と発言の一致や、本当の面白さは判定できません。ルール画面で「デモ判定」と明示します。

- `gpt-judge.js`：GPT用の1ラウンド1通信プロバイダー。

## 検証

`tests/flow_browser_check.py` はスマホ設定でタイトル→ルール→難易度→描画→3ラウンド→独立した結果を通して検証します。AI選択UIがないこと、ブラウザ戻る/進む、描画の維持、スマホでの自動フォーカス抑止、320〜1280pxの横はみ出しも確認します。下記CDP環境が必要で、外部AIは呼びません。

サーバー処理はPython標準ライブラリだけで検証できます。

```bash
python3 -m unittest discover -s tests -v
```

サーバーを起動し **http://127.0.0.1:8000/tests/index.html** を開くと、ブラウザ内でゲーム処理13項目（3ラウンド、勝敗、重複、二重送信、エラー時の復帰、ダメージ制限、描画・消去・undo、プロバイダー契約など）を確認できます。

### 更新後も古い敵や画面が表示される場合

起動中の `server.py` / `share.py` を Ctrl+C で停止し、いつもの起動コマンドで再起動してから画面を更新してください。PCは Ctrl+Shift+R、スマホは開いているゲームのタブを閉じてURLを開き直します。静的ファイルもキャッシュしない設定にしていますが、この設定の反映にはサーバー再起動が必要です。

採点待ちの確認：`tests/ranking_browser_check.py` は実通信の前に2秒の遅延を加え、自分のカットインが直ちに始まり、採点完了前にHPが減らず、採点とカットインの両方が終わる約2.5秒後に最初の被弾に進むことも検証します。これは模擬的な待ち時間の検証で、実AIの応答時間を保証するものではありません。AIへの依頼ではCPUの一言・採点理由・画像の根拠を簡潔に返すよう指定しています。
